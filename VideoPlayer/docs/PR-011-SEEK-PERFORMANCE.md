# PR-011：修復拖曳／跳轉造成多格卡頓

日期：2026-11-07。狀態：0.6.2 完成修復及驗收。

## 需求與工作計劃

拖曳其中一格時間軸時不拖慢其他格；點擊時間軸降低跳轉等待。保留暫停精準逐格、AB 操作及畫面設定。沿用既有 PR 工作流程，不新增功能或伺服器。

| 目標 | 狀態 | 驗證 |
|---|---|---|
| 重現與建立基準 | 完成 | 四格 1080p30、18 秒、GOP 300 素材，持續跳轉一格 |
| 分離原因並修復 | 完成 | 同一測試只改為非同步核心呼叫，跨格卡頓消失 |
| 回歸與交付 | 完成 | 11 單元測試、83 原生驗收、桌面拖曳與 AB、0.6.2 包及 PR |

## 原因與修復

原本在共用 GUI／OpenGL 執行緒呼叫同步 mpv_command、mpv_get_property、mpv_set_property。跳轉時播放核心可能等待同一執行緒渲染，形成互相等待，直到核心逾時才繼續，因此所有格子的畫面更新一起停頓。這與 [mpv render API 的執行緒限制](https://raw.githubusercontent.com/mpv-player/mpv/master/include/mpv/render.h) 相符。

排序後的三個假設為同步呼叫互等、重複拖曳命令、精準解碼成本。第一項經同素材前後對照證實；僅改用非同步命令／設定與屬性觀察快取，就已將卡頓消除。未降低精準解碼設定。

- 所有播放期間的核心命令及設定改用非同步 API，錯誤由事件回報。
- 播放位置、長度、尺寸、音量與暫停狀態由屬性通知更新快取；GUI／渲染不再同步查詢核心。
- 拖曳預覽最多每 50 ms 提交一次，重複位置不提交；釋放時立即送出尚未提交的最後精確位置。游標仍每次更新。
- AB 區間未改變時不重設播放核心；換片清除快取，避免錯過必要重設。
- 保留 absolute+exact 與原有精準逐格設定，沒有用關鍵幀近似替代最後位置。

## 實測

在同一電腦、四個實際解碼器、同一 1080p 長 GOP 素材下，測試連續六秒跳轉第一格。測試程式刻意保持原本每次跳轉重設 AB 的高壓模式，因此結果不依賴 UI 節流。

| 指標 | 修復前 | 非同步修復後 | 最終回歸 |
|---|---:|---:|---:|
| GUI 更新間隔 p95 | 230.13 ms | 16.81 ms | 16.85 ms |
| GUI 最長更新間隔 | 250.47 ms | 16.93 ms | 17.09 ms |
| 超過 100 ms 停頓 | 16 次 | 0 次 | 0 次 |
| 跳轉命令最長提交耗時 | 206.25 ms | 0.040 ms | 0.066 ms |

最終測試中，另一格在六秒期間前進 5.967 秒；結束連續拖曳後單次精準跳轉，49.25 ms 後觀察到目標播放位置。此為位置回報延遲，不等同獨立攝影機量測的螢幕首幀延遲，也不保證所有素材相同。

11 個單元測試通過，包含拖曳節流與放手最後位置；主程式 Clippy 及格式檢查通過。VFR 精準正反向逐格、獨立音量、五項調色與重置共 83 項原生 GPU 畫面驗收全部通過。桌面四格播放時點擊／拖曳時間軸可操作，跳出 AB 顯示循環暫停，回 A 恢復區間並保持暫停狀態。

## 重跑與交付

`cargo run --release --bin seek_perf -- <至少18秒影片> <report.json>`：執行真實四格解碼、持續跳轉及最後位置驗證，報告含 pass。門檻為六秒期間超過 120 次 GUI 更新、每次間隔小於 100 ms、另一格前進超過五秒、最終位置在 500 ms 內到達。硬體負載會影響門檻，測試素材與本機結果放在忽略的 verification 目錄。
